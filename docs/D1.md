# D1: Benchmarking Code

All code for the baseline benchmark in [Benchmarking](Benchmarking.md), split into three
sessions. Each session starts fresh and reads [dev.md](dev.md) as the spec.

---

## Session 1: Foundations

- `pyproject.toml`, with RDKit pinned to 2026.3.2
- `src/molscout/scoring/`: canonicalization, stereo-stripped matching, crop accuracy,
  whole-PDF precision, recall and F1 (micro and macro), 95% CIs
- Reader and validator for `predictions.csv`
- `src/molscout/data/`: molfile, SDF and internal ground-truth loaders
- `scripts/fetch_data.py` and `data/manifests/` for USPTO, UOB, JPO, CLEF and MolRecBench-Wild
- Internal split loader for `data/manifests/internal_split.csv`; scores by split
- Unit tests for all of the above

```
Work in MolScout/ (repo as-obaid/MolScout). Read MolScout/docs/dev.md,
MolScout/docs/Benchmarking.md and the Scoring Settings and Metrics sections of
MolScout/docs/dev-notes-log-stage.md first; they are the spec.

Build step 1 of the Build Order in dev.md, test-first:
1. pyproject.toml: Python 3.11+, package in src/molscout, RDKit pinned to 2026.3.2.
2. src/molscout/scoring/: canonical SMILES, stereo-stripped canonical SMILES, exact match.
   Crop scoring: accuracy (stereo-aware and stereo-stripped) and valid-output rate.
   Whole-PDF scoring: micro precision, recall, F1 pooled over molecules; macro precision
   and recall per paper; stereo-stripped precision, recall and F1.
   95% CIs: Wilson for accuracy and micro scores; bootstrap over papers (10,000
   resamples, fixed seed) for macro scores. Write them to scores.json.
   `*` is a valid atom: 5 ground-truth molecules contain it, so canonicalize it, never
   reject it.
   Invalid SMILES count as emitted and wrong. Duplicate predictions within a paper are
   deduplicated before scoring. Write these two choices into dev.md.
3. A reader and validator for the predictions.csv format in dev.md.
4. src/molscout/data/: loaders for molfile, SDF (JPO labels are SDfiles) and the internal
   ground-truth CSV (columns: paperID, name of molecule, canonical_SMILES; 222 rows).
   The internal set lives in data/internal/, which is gitignored and never committed.
5. scripts/fetch_data.py and data/manifests/ for USPTO, UOB, JPO, CLEF
   (github.com/Kohulan/OCSR_Review) and MolRecBench-Wild (Hugging Face).
6. A loader for data/manifests/internal_split.csv (frozen: papers 1, 16, 19 dev; 2, 4, 6
   test). Whole-PDF scores on Internal are reported for dev, test and all six. Do not
   edit the manifest.

Skills and agents:
- Plan first with superpowers:writing-plans; build with superpowers:test-driven-development
  and ecc:python-testing.
- Run independent parts in parallel with superpowers:dispatching-parallel-agents: scoring,
  loaders and fetch_data.py don't depend on each other.
- Review with the python-reviewer and mle-reviewer agents; finish with
  superpowers:verification-before-completion.

Done when unit tests pass and scoring a hand-made predictions file matches numbers computed
by hand. Commit with conventional messages; don't push until I review.
```

## Session 2: Structure Readers

- MolRecBench-Wild images exported from Parquet, and its CARBON graph labels converted to SMILES
- Seconds per item in `scores.json`, and `scripts/make_tables.py` for the Type 1 tables
- `benchmarks/slurm/run.sbatch` and the shared run harness that writes `meta.json`
- Tool folders for MolScribe, MolNexTR, DECIMER, MolVec, MolGlyph and OCSRGlyph, each with its own
  environment
- One config per tool × dataset: 30 configs
- All 30 runs scored in `benchmarks/results/`
- Type 1 results tables in Benchmarking.md filled in

```
Work in MolScout/ (repo as-obaid/MolScout, branch benchmark). Read MolScout/docs/dev.md
(Rules, Predictions Format, Scoring Rules, Running Benchmarks), MolScout/docs/Benchmarking.md
(Type 1) and the Session 2 checklist in MolScout/docs/dev-notes-log-stage.md first; they are
the spec.

Session 1 built scoring (`molscout score`, src/molscout/cli.py), the predictions.csv reader
(src/molscout/predictions.py), the molfile/SDF loaders and scripts/fetch_data.py. Reuse them;
don't rewrite them. Facts it established:
- Crop IDs are image file stems. Images are in data/raw/<dataset>/<NAME>/ and references in
  data/raw/<dataset>/<NAME>_mol_ref/. Score a run with:
  molscout score <predictions.csv> --references data/raw/uspto/USPTO_mol_ref -o <scores.json>
- 15 USPTO, 1 JPO and 15 CLEF references can't be read by RDKit and are excluded, so USPTO
  is scored on 5,704 crops. CLEF has 992 crops, not 961.
- data/raw/ is gitignored: run scripts/fetch_data.py on Explorer. Use Python 3.12 for the
  molscout environment.
- MolRecBench-Wild (5,024 crops, release 2026-08-19) stores its images inside Parquet files
  and its labels as CARBON molecular graphs, not SMILES.

Build steps 2 and 3 of the Build Order in dev.md on the Explorer cluster:
0. Before scoring CLEF, ask me whether a bare `*` should match labeled dummy atoms. CLEF
   R-groups canonicalize as [1*], [2*] (85 of 992 references), and readers usually output
   `*`. Record my answer in dev.md under Scoring Rules.
1. MolRecBench-Wild, test-first: export each Parquet image to
   data/raw/molrecbench_wild/images/<id>.png, and add a loader that turns each CARBON graph
   into SMILES. Graphs RDKit can't sanitize are excluded with a reason, as unreadable
   references are. Spot-check 20 conversions against their images. Check how the
   MolRecBench-Wild paper scores before comparing with its published 41.05% for MolScribe.
2. Speed, test-first: add seconds per item (mean and median) to scores.json from the
   `seconds` column. Add scripts/make_tables.py, which builds the Type 1 tables in
   Benchmarking.md, including "Valid output and speed, all datasets pooled", from
   benchmarks/results/*/scores.json.
3. benchmarks/slurm/run.sbatch taking one config path, runnable as a job array, and a
   harness that runs a tool's run.py in that tool's own environment as a subprocess,
   validates predictions.csv with read_predictions, runs molscout score, and writes
   predictions.csv, scores.json, config.yaml and meta.json (git commit, environment lock,
   hardware, timing) to benchmarks/results/<tool>__<dataset>/. Tool code never imports
   molscout; run.py writes the predictions.csv columns itself.
4. benchmarks/tools/structure_readers/molscribe/: environment file + run.py. Run it on USPTO
   first. It must land within the published 82.1–93.8% range (88.4% with all stereo, per the
   Glyph README); if not, find out why before going further.
5. The same for molnextr/, decimer/, molvec/, molglyph/ and ocsrglyph/, each in its own
   environment. MolGlyph runs through BioMiner's code
   (BioMiner/MolScribe/molscribe/interface_molglyph.py) with gated weights from Hugging Face
   (jiaxianustc/MolGlyph; access granted to muhammad-ob). OCSRGlyph installs from
   github.com/EdisonScientific/glyph with `uv sync --extra ocsr`.
6. Configs for all 6 tools × 5 datasets (USPTO, UOB, JPO, CLEF, MolRecBench-Wild), each
   recording tool version and checkpoint hash; run all 30.
7. Fill the Type 1 tables in docs/Benchmarking.md with scripts/make_tables.py.

Skills and agents:
- Plan first with superpowers:writing-plans; build with superpowers:test-driven-development
  and ecc:python-testing.
- Use the explorer-cluster skill for every cluster step: SSH, environments, sbatch, logs.
- Once MolScribe on USPTO is verified, build molnextr/, decimer/, molvec/, molglyph/ and
  ocsrglyph/ in parallel, one agent per tool, with superpowers:subagent-driven-development.
- Use the pytorch-build-resolver agent for CUDA or environment failures, and
  superpowers:systematic-debugging if a score lands outside the published range.
- Review with the python-reviewer and mle-reviewer agents; finish with
  superpowers:verification-before-completion.

Done when all 30 runs are scored in benchmarks/results/, MolScribe on USPTO is within the
published range, and the Type 1 tables are generated from scores.json. Add verified tool
quirks to Course-Project/Docs/log.md under Tools. Commit with conventional messages; don't
push until I review.
```
