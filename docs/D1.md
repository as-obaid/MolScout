# D1: Benchmarking Code

All code for the baseline benchmark in [Benchmarking](Benchmarking.md), split into three
sessions. Each session starts fresh and reads [dev.md](dev.md) as the spec.

---

## Session 1: Foundations

- `pyproject.toml`, with RDKit pinned to 2026.3.2
- `src/molscout/scoring/`: canonicalization, stereo-stripped matching, crop accuracy,
  whole-PDF precision, recall and F1 (micro and macro)
- Reader and validator for `predictions.csv`
- `src/molscout/data/`: molfile, SDF and internal ground-truth loaders
- `scripts/fetch_data.py` and `data/manifests/` for USPTO, UOB, JPO, CLEF and MolRecBench-Wild
- `scripts/select_test_papers.py` and the held-out paper list
- Unit tests for all of the above

```
Work in MolScout/ (repo as-obaid/MolScout). Read MolScout/docs/dev.md and
MolScout/docs/Benchmarking.md first; they are the spec. docs/ is gitignored, keep it that way.

Build step 1 of the Build Order in dev.md, test-first:
1. pyproject.toml: Python 3.11+, package in src/molscout, RDKit pinned to 2026.3.2.
2. src/molscout/scoring/: canonical SMILES, stereo-stripped canonical SMILES, exact match.
   Crop scoring: accuracy (stereo-aware and stereo-stripped) and valid-output rate.
   Whole-PDF scoring: micro precision, recall, F1 pooled over molecules; macro precision
   and recall per paper; stereo-stripped precision and recall.
   Invalid SMILES count as emitted and wrong. Duplicate predictions within a paper are
   deduplicated before scoring. Write these two choices into dev.md.
3. A reader and validator for the predictions.csv format in dev.md.
4. src/molscout/data/: loaders for molfile, SDF (JPO labels are SDfiles) and the internal
   ground-truth CSV (columns: paperID, name of molecule, canonical_SMILES; 222 rows).
   The internal set lives in Course-Project/Data/ and is never copied into the repo.
5. scripts/fetch_data.py and data/manifests/ for USPTO, UOB, JPO, CLEF
   (github.com/Kohulan/OCSR_Review) and MolRecBench-Wild (Hugging Face).
6. scripts/select_test_papers.py: choose the held-out internal papers with a fixed seed and
   write the list to data/manifests/.

Skills and agents:
- Plan first with superpowers:writing-plans; build with superpowers:test-driven-development
  and ecc:python-testing.
- Run independent parts in parallel with superpowers:dispatching-parallel-agents: scoring,
  loaders and fetch_data.py don't depend on each other.
- Review with the python-reviewer and mle-reviewer agents; finish with
  superpowers:verification-before-completion.

Done when unit tests pass and scoring a hand-made predictions file matches numbers computed
by hand. Commit with conventional messages; don't push until I review.
```

## Session 2: Structure Readers

- `benchmarks/slurm/run.sbatch` and the shared run harness that writes `meta.json`
- Tool folders for MolScribe, MolNexTR, DECIMER and MolVec, each with its own environment
- One config per tool × dataset: 20 configs
- All 20 runs scored in `benchmarks/results/`
- Type 1 results tables in Benchmarking.md filled in

```
Work in MolScout/. Read MolScout/docs/dev.md and MolScout/docs/Benchmarking.md first.
Session 1 built scoring, loaders and fetch_data.py; reuse them, don't rewrite them.

Build steps 2 and 3 of the Build Order in dev.md on the Explorer cluster (use the
explorer-cluster skill):
1. benchmarks/slurm/run.sbatch taking one config path, runnable as a job array, and a
   harness that writes predictions.csv, scores.json, config.yaml and meta.json (git commit,
   environment lock, hardware, timing) to benchmarks/results/<tool>__<dataset>/.
2. benchmarks/tools/structure_readers/molscribe/: environment file + run.py. Run it on USPTO
   first. It must land within the published 82.1–93.8% range; if not, find out why before
   going further.
3. The same for molnextr/, decimer/ and molvec/, each in its own environment.
4. Configs for all 4 tools × 5 datasets (USPTO, UOB, JPO, CLEF, MolRecBench-Wild); run all 20.
5. Fill the Type 1 results tables in docs/Benchmarking.md from scores.json.

Skills and agents:
- Use the explorer-cluster skill for every cluster step: SSH, environments, sbatch, logs.
- Once MolScribe on USPTO is verified, build molnextr/, decimer/ and molvec/ in parallel,
  one agent per tool, with superpowers:subagent-driven-development.
- Use the pytorch-build-resolver agent for CUDA or environment failures, and
  superpowers:systematic-debugging if a score lands outside the published range.
- Review with the python-reviewer and mle-reviewer agents; finish with
  superpowers:verification-before-completion.

Add verified tool quirks to Course-Project/Docs/log.md under Tools. Commit with conventional
messages; don't push until I review.
```

## Session 3: Complete Systems and Agent

- Tool folders for DECIMER.ai, OpenChemIE and BioMiner
- BioVista manifest and PDF fetch by DOI, recording PDFs obtained
- Runs on BioVista and Internal: 6 runs scored
- Agent goal prompt and a converter from agent output to `predictions.csv`
- Type 2 results tables in Benchmarking.md filled in

```
Work in MolScout/. Read MolScout/docs/dev.md and MolScout/docs/Benchmarking.md first.
Sessions 1 and 2 built scoring, loaders, the harness and the structure-reader runs; reuse
them.

Build steps 4 and 5 of the Build Order in dev.md on Explorer:
1. BioVista: add its labels to data/manifests/ and extend fetch_data.py to fetch PDFs by DOI.
   Record how many PDFs were obtained; PDFs stay in data/raw/.
2. benchmarks/tools/complete_systems/decimer_ai/ and openchemie/: environment file + run.py
   that takes whole PDFs and writes predictions.csv with page and bbox.

   Oct 8, stop, and record why in Benchmarking.md and Course-Project/Docs/log.md.
4. Configs and runs for all 3 systems on BioVista and Internal. Internal PDFs are read from
   Course-Project/Data/ and never copied into the repo.
5. benchmarks/tools/agents/claude_code/: the fixed goal prompt, and a converter from the
   agent's output to predictions.csv.
6. Fill the Type 2 results tables in docs/Benchmarking.md from scores.json.

Skills and agents:
- Use the explorer-cluster skill for every cluster step.
- Build decimer_ai/, openchemie/ and biominer/ in parallel, one agent per system, with
  superpowers:subagent-driven-development; the agent converter is a fourth, independent task.
- Use the pytorch-build-resolver agent for CUDA or environment failures, and
  superpowers:systematic-debugging for wrong or empty outputs.
- Review with the python-reviewer and mle-reviewer agents; finish with
  superpowers:verification-before-completion.

Add verified tool quirks to Course-Project/Docs/log.md under Tools. Commit with conventional
messages; don't push until I review.
```

The three agent runs are done by hand afterwards: one fresh Claude Code session per run, given
the goal prompt from `benchmarks/tools/agents/claude_code/`, then scored with the converter.
